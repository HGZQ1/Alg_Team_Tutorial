# ROS概论 

在本章将会教你ROS2基础的工作空间、节点、话题通信。

**ROS（Robot Operating System,机器人操作系统），ROS包含大量搭建机器人所需的软件和工具，是目前最广泛的机器人操作系统**。为了让你更好的理解ROS与机器人的关系，我们来做个比喻，一个温度传感器可以测量温度（相当于人类皮肤）,一个电机可以执行动作（相当于肌肉关节），然后上位机的决策系统就像人类的大脑，温度传感器把温度信号传给决策系统，决策系统做出判断，然后控制电机旋转，而ROS就充当着这其中信号交流的作用，把温度信号传给决策系统，把运动信号传给关节电机，所以ROS就相当于机器人的神经网络。

与单片机的通信不同，ROS2因为是部署于强大的算力平台，所以它不再局限于控制电机运动/接收反馈，可以完美传递图像数据，高频率/复杂的外接传感器数据（雷达），内部多模块（决策系统，感知系统，通信系统）的相互通信，且内部的工具软件支持数据可视化（可以看见深度相机的RGB-D所有图像，YOLO检测效果，雷达建图效果，雷达里程计等等），且支持动态仿真，让机器人的开发更为简单便捷。所以**ROS2本质就是用于快速搭建机器人的软件库（核心功能是通信）和工具集。**  

上面说了ROS2的核心功能是通信。
## ROS2通信机制 
ROS2的四大通信机制分别是**话题通讯（Topic）、服务通信（Service）、参数通信（Parameter）、动作通信（Action）。** 
- **话题通信**：是指发布 - 订阅（Publish-Subscribe）,即发布者将话题发布到某个话题上，订阅者订阅话题即可获取数据，属于单向传递。例如可以通过将机器人的位置信息发布到某个名称的话题，订阅了该话题的节点就可以获取机器人的位置数据了。人话：微信公众号。（也是最常用的通信）
- **服务通信**：分为客户端和服务端，客户端可以发送请求到服务端，由服务端处理并返回结果，属于双向传递。人话:网站访问 
- **动作通信**：属于双向传递，跟服务通信类似，同样有动作客户端和动作服务端，相比起服务通信，动作通信服务端可以在处理客户端请求时随时反馈处理进度和取消服务，动作通信往往用于复杂的机器人行为。
- **参数通信**：机器人参数的设置和读取

## 节点 

简单来说 ROS2 节点（Node）就是机器人系统里面的一个独立干活的小程序，是ROS2中的最基本的**计算单元**。也就是机器人体内的一个“工作细胞”，各司其职，共同构成一个完整的机器人系统。一个完整的机器人正常运行，背后往往是二三十个节点在工作。 

ROS2的设计强调模块化，每个节点最好只负责单一的、明确的任务。就像一个复杂的机器人系统中有一个节点专门负责控制轮子速度、一个专门负责读取激光雷达数据。这种编写使得代码更容易编写、调试和维护。 

相比起我们玩过的单片机将代码写为一个整体，所有功能像一套库，写一个主程序/main函数然后把所有功能调用进去。ROS2里面没有主程序这一说法，ROS2反而是将一个完整的程序分解为一个个独立的节点，而靠通信连成一张网；节点间不相互调用，靠话题收发信息，每个节点只关心自己的输入和输出。分割成一个个小的节点，可以使程序在运行时不会因为单一节点崩溃而导致整个程序整体瘫痪。（你的身体不会因为一个细胞的死亡而崩坏） 

## ROS2开发环境搭建 
### 工作空间 
工作空间（workspace）是在进行开发时非常重要的一个概念，工作空间是一个目录，里面包含了ROS2的源代码、编译后的文件、安装后的文件等。工作空间的结构如下：
```
~/ros2_ws/
├── src/
├── build/
├── install/
└── log/
```
所以，简单来说它其实就是一个文件夹，但是里面包含了ROS2的源代码、编译后的文件、安装后的文件等。
- **src**：存放源代码的目录，里面可以包含多个ROS2包（package），每个包都是一个独立的功能模块。
- **build**：存放编译后的文件的目录，里面包含了编译后的目标文件、库文件等。(编译空间)
- **install**：存放安装后的文件的目录，里面包含了安装后的可执行文件、库文件、配置文件等。（安装空间）  
- **log**：存放日志文件的目录，里面包含了编译、运行等过程中的日志文件。 （日志空间）
- **注意**：工作空间的目录结构是固定的，不能随意更改，否则会导致编译失败。
其中：log,build,install目录是编译后自动生成的，src目录是我们自己创建的。所以log,build,install这三个文件夹就是我们常说的编译产物，这些删了也没事，下次运行需要重新构建而已，且编译产物一般不需要上传git仓库（谁给我上传一堆编译文件上来自己清理掉，纯占地方） 

一般情况笔者习惯直接先创建一个总的project文件夹，然后在里面创建一个ros2_ws工作空间，里面再创建src文件夹，最后在src文件夹里面创建自己的包（package）；与ros2_ws同级的再创建一个sim_ws文件夹，这样就方便管理。 
```
~/projects/
├── ros2_ws/ （放真机部署的代码的ROS2工作空间）
│   ├── src/
│   ├── build/
│   ├── install/
│   └── log/
├── readme.md (放项目说明文档或者一些你的碎碎念)
└── sim_ws/   (放仿真环境代码的ROS2工作空间)
    ├── src/
    ├── build/
    ├── install/
    └── log/ 
``` 
在ubuntu开发时通常需要用到许多命令，有些命令会涉及路径，例如典型的source命令，source命令是用来加载环境变量的，加载环境变量后才能使用ROS2的命令和工具。但是如果在说明文档或者在实际开发文件中把文件路径写死为你自己开发机的绝对路径，那么其他人就无法使用你的代码了，所以我们需要使用以/projects为根的相对路径来代替绝对路径。 

简单来说工作空间就他妈一堆文件夹。 

### 功能包 
功能包（Package）是组织和管理机器人软件代码的基本单元，简单来说如果节点是一个手机APP，则功能包就是开发这个APP时的工程文件夹。 

功能包里面包含着许多东西： 
- 源代码：也就是我们编写的节点的代码 
- 配置文件：这是功能包的身份证和说明书：Package.xml:定义功能包的名称、版本、作者、**依赖项**。setup.py/CMakeLists.txt:告诉系统如何构建和安装这个包，以及如何注册为可执行文件。
- 启动文件：即launch文件，用于一次性启动多个节点的脚本文件 
- 自定义消息接口：如消息、服务、动作的数据结构定义 
- 其他资源：例如参数配置文件（YAML）、模型文件、权重文件等等。 

功能包有着以下特点：
- 模块化和高内聚：功能包遵循一个功能包只解决一个特定区域的问题的原则。例如camera_driver只负责相机驱动，slam_toolbox只负责建图。这让代码结构更加清晰。 
- 依赖管理：通过package.xml，ROS2的构建工具colcon能自动理解各个包之间的依赖关系，按正确顺序编译。
- 代码复用与分享：你可以直接把一个完整的、封装好的包发给别人或发布到github，别人下载后编译即可运行。 

所以功能包就是ROS2里面封装节点的方式，你在里面写节点，配依赖，然后colcon build把它编译成一个可以被机器人系统直接调用的独立组建。

## 练习

多说无益，现在来上手教你们完整创建一个工作空间并运行一个Hello ROS2的节点 

打开终端，先加载ROS2底层环境  
```bash 
source /opt/ros/humble/setup.bash 
``` 
接下来创建工作空间 

```bash 
mkdir -p ~/ros2_hello_ws/src 
cd ~/ros2_hello_ws/src
``` 
创建一个Python功能包 
```bash 
ros2 pkg create --build-type ament_python hello_ros2_py --dependencies rclpy
```
然后当前的目录就是如下 
```text
~/ros2_hello_ws/
├── src/
│   └── hello_ros2_py/  <--这就是一个完整的功能包了
│       ├── package.xml # 配置文件
│       ├── setup.py  # 依赖项
│       ├── setup.cfg
│       ├── resource/
│       │   └── hello_ros2_py
│       ├── test/
│       └── hello_ros2_py/
│           └── __init__.py  # python标识文件，一般为空
├── build/
├── install/   #构建产物就会放到这里
└── log/
```
创建python节点 
```bash
cd ~/ros2_hello_ws/src/hello_ros2_py/hello_ros2_py 
``` 
在该路径下新建一个文件命名为hello_node.py,然后写入以下代码 
```python
import rclpy  # 导入ROS2的python客户端，C++的则是rclcpp 
from rclpy.node import Node # 从rclpy.node导入Node（节点）类


def main():   # 定义一个main函数,默认传参为None(无参数)
    rclpy.init()  # 这是每个ROS2python节点运行前必须调用的第一步，负责初始化ROS2通信中间件，上下文，日志等等 
    node = Node('hello_node') # 即创建一个名为“hello_node”的节点实例，并赋值给node,有了node实例就可以通过他来订阅和接受话题了
    node.get_logger().info('Hello, ROS 2!') # 通过节点日志器打印一条INFO级别的日志：Hello ROS2!
    rclpy.spin(node) # 创建完成节点后用spin方式来启动一个节点，并不断循环检查被其运行的节点是否收到新的话题数据等事件
    rclpy.shutdown() # 用于关闭python客户端库，释放初始化资源，即停止ROS2通信，清理上下文

if __name__ == '__main__':  # python的模块入口判断 当这个.py文件被直接运行时，__name__的值是__main__，条件成立执行main();当这个文件被当作模块import导入时，__name__的值是hello_node,不会直接自动执行。故这行代码意思是“只有这个文件被直接运行时才调用main(),被别的文件调用时不自动执行”
    main()
``` 
好的，现在你有了一个python节点了。

```text
程序启动
  ↓
import rclpy、Node
  ↓
定义 main()
  ↓
__name__ == '__main__' 成立
  ↓
调用 main()
  ↓
rclpy.init()        初始化 ROS 2
  ↓
Node('hello_node')  创建节点
  ↓
get_logger().info() 打印 Hello, ROS 2!
  ↓
rclpy.shutdown()    关闭 ROS 2
  ↓
程序退出
```
修改setup.py注册可执行节点：打开 ~/ros2_hello_ws/src/hello_ros2_py/setup.py,重点找到'entry_points'修改好后如下 

```python
from setuptools import setup

package_name = 'hello_ros2_py'

setup(
    name=package_name,
    version='0.0.0',
    packages=[package_name],
    data_files=[
        ('share/ament_index/resource_index/packages',
            ['resource/' + package_name]),
        ('share/' + package_name, ['package.xml']),
    ],
    install_requires=['setuptools'],
    zip_safe=True,
    maintainer='your_name',
    maintainer_email='you@example.com',
    description='ROS 2 Python hello world',
    license='Apache-2.0',
    tests_require=['pytest'],
    entry_points={
        'console_scripts': [
            'hello_node = hello_ros2_py.hello_node:main',  #<-看这
        ],
    },
)
``` 

然后开始编译工作空间，打开你的终端 
```bash
cd ~/ros2_hello_ws
colcon build --packages-select hello_ros2_py
```
在电脑最上面弹出来colcon build success 的通知后即可开始运行 

激活环境并运行 
```bash
source ~/ros2_hello_ws/install/setup.bash
ros2 run hello_ros2_py hello_node
```
输出 
```text
[INFO] [1720000000.000000000] [hello_node]: Hello, ROS 2! 

[INFO] : 日志级别 
[1720000000.000000000]：时间戳 （秒/纳秒） 
[hello_node] ：节点名 
Hello, ROS 2! ：消息内容
``` 
如何，是不是费尽九牛二虎之力终于打印了一个Hello ROS2,相比起我们平时写的python，C++是不是麻烦了很多。这就是ROS2，现在动手写了第一个节点，接下来就好讲解了。
