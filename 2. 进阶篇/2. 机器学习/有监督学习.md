# 有监督学习：从数据到 YOLO 模型

## 1. 什么是有监督学习

**有监督学习，就是让模型通过“输入 + 正确答案”学习规律，再预测没见过的数据。**
例如：输入一张番茄图片，答案包含每个番茄的位置、轮廓和成熟度；模型反复预测，与标注比较得到损失（loss），再通过反向传播更新参数。

常见任务有分类（是否成熟）、回归（预测重量）、目标检测（类别与矩形框）和实例分割（类别与每个目标的轮廓）。
训练的目标是让模型在新场景中也能正确预测，这种能力叫**泛化能力**。

本章参考 [实际 YOLO 案例](实际YOLO案例/README_归档说明.md)：

| 案例 | 标注对象 | 类别 |
|---|---|---|
| 番茄成熟度识别 | 每个番茄果实的轮廓 | `tomato_R` 成熟、`tomato_G` 未成熟 |
| 玉米大斑病检测 | 每株玉米的轮廓 | `maize_01` 健康、`maize_02` 大斑病 |

两例实际使用的是 **YOLOv8 实例分割**。下面以番茄为主线，完成：采集数据 → 标注 → 划分数据集 → 训练与验证 → 结果分析 → 改进。

## 2. 采集数据：先想清楚模型会在哪里使用

### 2.1 数据从哪里来

- **实拍**：使用机器人实际使用的相机或者用自己的手机和相机，在温室或田间拍照、录视频；视频按时间间隔抽帧，再去掉近乎相同的画面。
- **公开数据集**：案例使用 iTomato-Seg-UA 的田间/温室图片，以及 Kaggle 的成熟/未成熟番茄图片。下载后检查授权、标注类型和类别定义。

采集时主动覆盖不同光照、距离、视角、背景、成熟度和遮挡程度，避免只拍清晰、居中、全红的番茄。
保留原始图片，记录拍摄地点、日期、视频来源；模糊到无法判断的图片单独存放，避免强行标注。
适量收集**没有番茄的背景图**，帮助模型减少误报。

### 2.2 训练集、验证集与标注的关系

**标注是给图片添加答案；训练集、验证集是按用途划分的数据，两者都需要标注。**“标注集”通常指已标注的数据，不是验证集的同义词。

| 集合 | 用途 | 是否更新模型参数 |
|---|---|---|
| 训练集 `train` | 学习图片与标注之间的规律 | 是 |
| 验证集 `val` | 每轮检查效果，选择模型和训练参数 | 否 |
| 测试集 `test`（可选） | 方案确定后，做最终独立评估 | 否 |

可先按约 8:2 划分训练/验证集；有足够数据时，可按约 8:1:1 留出测试集。
案例最终为训练 676 张、验证 118 张、测试 55 张，共 849 张，并非必须照搬这个比例。

- **先按视频、拍摄批次或场景分组，再划分集合**；同一视频的相邻帧不能分到训练和验证两边，防止数据泄漏。
- 各集合尽量覆盖主要类别和典型场景，固定划分种子（如 `42`），保存文件清单。
- 数据增强只用于训练集；先划分，再增强，避免原图与增强图跨集合重复。
- 验证集用于迭代，测试集保留到最终评估；不能看到测试结果后反复调参，再把它当独立成绩。

## 3. 标注：把“正确答案”统一起来

### 3.1 先定标准，再开始画

番茄案例规定 `0 = tomato_R`（全红/橙红、无明显绿色），`1 = tomato_G`（绿色、浅橙、转色期）。
每个果实单独画一个 polygon（多边形），相邻果实不能合并。遮挡部分是否补全、边缘截断如何处理，必须在整个数据集中保持一致。
案例对遮挡部分按果实轮廓补全，截断处沿画面边界闭合；这是该项目的约定。

使用 **X-AnyLabeling**：打开图片目录 → 选择多边形工具 → 沿轮廓描点 → 选择类别 → 保存同名 JSON → 导出 **YOLO Segmentation** 标签。
AI 预标也要人工复核，尤其检查遮挡、小目标和成熟度边界。

### 3.2 YOLO 分割标签长什么样

每张图片对应一个同名 `.txt`，每行一个目标，格式为：

```text
类别ID x1 y1 x2 y2 x3 y3 ...
```

坐标归一化到 `[0, 1]`：`x = 像素横坐标 / 图片宽`，`y = 像素纵坐标 / 图片高`；每个多边形至少 3 个点。
例如下面一行表示类别 0 的四边形，仅用于说明格式：

```text
0 0.30 0.20 0.60 0.20 0.60 0.70 0.30 0.70
```

分割标签与检测标签的 `类别ID 中心x 中心y 宽 高` 不同，不能混用。格式详见 [Ultralytics 分割数据说明](https://docs.ultralytics.com/datasets/segment/)。

### 3.3 合并数据前必须核对

- 案例中 iTomato 的 `green(0) / ripe(1) / ripening(2)` 应映射为 `1 / 0 / 1`；Kaggle 的 `unriped(0) / riped(1)` 应映射为 `1 / 0`。
- **类别 ID 映射正确，不代表成熟度标准一致**。案例还人工修正了 89 个误标实例，统一“转色期不算成熟”。
- 抽样叠加显示图片与标签，检查漏标、错类、轮廓偏移、坐标越界，以及图片与标签是否同名。
- 有目标但未标注的图不能当背景图；确认没有目标的背景图可配空 `.txt`，不能被“跳过未标注图片”选项误删。

详细操作见 [番茄数据集标注方法手册](实际YOLO案例/番茄数据集标注方法手册.md)。

## 4. 训练前的目录与配置

以 `E:/yolo_tomato/` 为训练项目根目录，沿用番茄案例的 `train/images` 组织方式：

```text
yolo_tomato/
├── train.py
├── evaluate.py
├── yolov8n-seg.pt             # 预训练权重
├── dataset/
│   ├── data.yaml
│   ├── train/
│   │   ├── images/           # 如 001.jpg
│   │   └── labels/           # 对应 001.txt
│   ├── val/
│   │   ├── images/
│   │   └── labels/
│   └── test/                 # 若不留测试集，可省略
│       ├── images/
│       └── labels/
└── runs/                     # 训练时自动生成
```

这是需要准备的训练目录；本仓库的案例文件夹提供教学说明，图片、标签和权重需另行准备。
玉米案例采用 `images/train`、`labels/train` 等结构，同样可用；关键是图片与标签路径对应，YAML 指向正确的图片目录。

在 `dataset/data.yaml` 中填写：

```yaml
path: E:/yolo_tomato/dataset  # 改成当前机器的数据集绝对路径
train: train/images
val: val/images
test: test/images            # 没有测试集就删除这一行
names:
  0: tomato_R
  1: tomato_G
```

`train/val/test` 相对于 `path`；类别 ID 必须与标签一致。换机器时修改 `path`，避免直接照抄案例作者的盘符。

## 5. 核心训练代码：训练集学习，验证集检查

先按 [PyTorch 入门](<PyTorch入门 .md>) 配好 PyTorch、Ultralytics 和 GPU 环境，并记录版本。
下面参数参考番茄案例，使用预训练的 `yolov8n-seg.pt` 做迁移学习；首次加载时若本地没有权重，需要联网下载。

保存为 `train.py`，在项目根目录执行 `python train.py`：

```python
from pathlib import Path
import torch
from ultralytics import YOLO

if __name__ == "__main__":  # Windows 多进程训练需要此入口保护
    root = Path(__file__).resolve().parent
    device = 0 if torch.cuda.is_available() else "cpu"
    model = YOLO("yolov8n-seg.pt")
    model.train(
        data=str(root / "dataset/data.yaml"),
        epochs=150,
        imgsz=960,
        batch=8,
        device=device,
        workers=2,
        patience=50,
        seed=42,
        val=True,
        amp=False,       # 案例为绕过 AMP 自检问题而关闭
        copy_paste=0.1,
        hsv_h=0.0,       # 成熟度依赖颜色，避免色相改变标签含义
        plots=True,
        project=str(root / "runs/segment"),
        name="tomato_seg",
    )
```

先把 `epochs` 改成 `3`、`imgsz` 改成 `640` 跑通数据与环境，再开始正式训练；CPU 可用于检查流程，完整训练建议用 GPU。

| 参数 | 含义与调整方式 |
|---|---|
| `epochs` | 最多训练多少轮；一轮会遍历训练集 |
| `imgsz` | 输入尺寸；增大有利于保留小目标细节，也增加计算和显存开销 |
| `batch` | 每批图片数；显存不足先从 8 降到 4 或 2 |
| `patience` | 验证表现连续多少轮未改善后早停 |
| `val=True` | 每轮在验证集上评估，验证时不更新权重 |
| `copy_paste` | 分割任务的数据增强，增加目标组合多样性 |

训练接口与参数见 [Ultralytics 训练说明](https://docs.ultralytics.com/modes/train/)。
训练完成后查看日志给出的目录，首次通常为 `runs/segment/tomato_seg/`；重复运行可能生成带编号的新目录。
其中 `weights/best.pt` 是验证综合表现最好的权重，`last.pt` 是最后一轮权重；`results.csv/png` 保存指标与曲线，还会生成混淆矩阵和验证预测图。

## 6. 结果分析：同时看指标、曲线和图片

保存以下代码为 `evaluate.py`，执行 `python evaluate.py`；若训练目录带编号，修改权重路径：

```python
from pathlib import Path
from ultralytics import YOLO

if __name__ == "__main__":
    root = Path(__file__).resolve().parent
    model = YOLO(str(root / "runs/segment/tomato_seg/weights/best.pt"))
    data = str(root / "dataset/data.yaml")
    metrics = model.val(data=data, split="val", imgsz=960, plots=True)
    print("Mask mAP50:", metrics.seg.map50)
    print("Mask mAP50-95:", metrics.seg.map)
    model.predict(source=str(root / "dataset/val/images"),
                  imgsz=960, conf=0.5, save=True)
    # 方案确定后才取消下一行注释，评估独立测试集：
    # model.val(data=data, split="test", imgsz=960)
```

分割模型同时报告 Box（框）和 Mask（轮廓）指标；轮廓任务重点看 Mask。接口见 [Ultralytics 分割说明](https://docs.ultralytics.com/tasks/segment/)。

| 观察项 | 怎么理解 |
|---|---|
| Precision（精确率） | 预测出的目标中有多少是对的；低时误检较多 |
| Recall（召回率） | 实际目标中找到了多少；低时漏检较多 |
| mAP50 | 在 IoU=0.5 的匹配条件下，汇总各类别的检测/分割表现 |
| mAP50-95 | 在多个、更严格的 IoU 阈值下取平均，更能反映定位与轮廓质量 |
| loss 曲线 | 训练 loss 降而验证 loss 持续升、验证指标下降，提示过拟合 |
| 混淆矩阵、预测图 | 找出成熟/未成熟混淆、漏检、误检及轮廓偏差 |

IoU 是预测区域与真实区域的“交集面积 / 并集面积”。mAP 是跨置信度的综合指标；单次推理的 `conf` 则决定保留哪些预测。
番茄案例最终验证 Mask mAP50 为 **0.834**、mAP50-95 为 **0.638**，Precision/Recall 为 **0.869/0.732**，仍有漏检空间。
玉米案例验证 Mask mAP50 为 **0.977**，全新场景测试为 **0.956**，说明还需要检查新场景表现。

## 7. 根据效果改数据、改训练

**先定位具体错误，再针对原因改进；不要只增加训练轮数。**

| 现象 | 优先改数据 | 再考虑改训练或推理 |
|---|---|---|
| 偏橙番茄被当成熟 | 统一成熟标准，修正错标，补充转色期样本 | 减弱会改变成熟含义的颜色增强 |
| 阴影里的红番茄被判未成熟 | 补拍阴影、逆光和不同曝光样本 | 使用适度亮度增强 |
| 遮挡、小目标、绿番茄漏检 | 补充对应难样本并查漏标，仿真作为补充 | 尝试增大 `imgsz`、适度复制粘贴增强 |
| 叶片等背景被误识别 | 加入背景负样本与易混淆物体 | 根据验证集 PR/F1 曲线选择 `conf` |
| 训练好、验证差 | 检查场景覆盖、样本重复和类别分布，增加独立数据 | 早停、适度增强，尝试更小模型 |
| 训练和验证都差 | 先查类别映射、标签质量及任务格式 | 再调学习率、训练轮数或模型容量 |

案例通过纠正标注、补充 110 张仿真图、将输入尺寸从 640 提到 960 来迭代，说明数据质量和场景覆盖同样关键。
降低 `conf` 通常能减少漏检，也会增加误检；采摘任务需重点检查“未成熟被判成熟”的代价。
每次只改一类因素，记录数据版本、参数、验证指标与典型错例；**使用固定验证集比较**，验证集变化后的分数不能直接横比。
从验证和现场试跑中整理错例，补采相似但独立的图片加入训练集，保留原有验证/测试样本的独立性，再训练、再评估。

案例细节见 [番茄成熟识别模型训练全流程](实际YOLO案例/番茄成熟识别模型_训练全流程.md)。
