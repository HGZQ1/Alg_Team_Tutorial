## 1. 项目背景与目标

### 1.1 采摘逻辑：等全红才摘

机器人只在番茄**完全成熟（全红/橙红）**时才采摘，绿色、浅橙、转色期的都不摘。视觉模块不仅要"找到番茄"，还要判断它的**精确轮廓和成熟度**，因此选用实例分割。

| 任务类型 | 输出 | 用途 |
|---|---|---|
| 目标检测 | 矩形框 | 知道"哪里有番茄" |
| **实例分割** | 贴合轮廓的 mask | 知道番茄精确形状 + 成熟度，供机械臂规划抓取 |

### 1.2 技术选型

| 项 | 选择 |
|---|---|
| 框架 | Ultralytics 8.4.164 |
| 模型 | **YOLOv8n-seg**（nano，速度快、适合边缘实时） |
| 底层 | PyTorch 2.5.1 + CUDA 12.1 |

## 3. 数据收集

### 3.1 选数据集的三个原则

1. **贴近真实场景**：田间、温室、光照变化；
2. **有分割标注**：需要多边形，不能只有框；
3. **开源合规**：注意 License。

### 3.2 两个数据集

#### 数据集 1：iTomato-Seg-UA（主力，550 张）

| 项 | 内容 |
|---|---|
| 来源 | Zenodo，DOI `10.5281/zenodo.17226397` |
| License | CC BY 4.0（需署名） |
| 内容 | 田间/温室实拍，**3 类**：green / ripe / ripening |
| 作用 | 训练主力，场景真实 |

#### 数据集 2：Kaggle Ripe and Unripe Tomatoes（补充，177 张）

| 项 | 内容 |
|---|---|
| 来源 | Kaggle（作者 sumn2u） |
| License | CC BY-SA 4.0 |
| 内容 | 白底产品图，**2 类**：riped / unriped |
| 作用 | 成熟/未成熟区分清晰，补充判定标准 |

### 3.3 为什么多数据集融合

- iTomato 场景真实，但"转色期"归类与业务需求可能冲突；
- Kaggle 类别清晰但场景单一（白底）；
- 融合 + 统一标准，让模型既认识真实场景、又严格区分成熟度。

> 融合前最关键的检查：**类别映射和标注口径是否一致**（见第 4、5 章）。

## 4. 数据预处理与类别映射

### 4.1 YOLO-seg 标签格式

每张图片对应同名 `.txt`，放在 `labels/`，每行一个实例：

```
<类别id> x1 y1 x2 y2 x3 y3 ...
```

- 坐标全部**归一化到 0~1**（像素坐标分别除以图片宽、高）；
- 类别 id 从 0 开始，对应 data.yaml 的 `names` 顺序。

### 4.2 类别映射（本项目最大的坑）

两个数据集的**类别 id 顺序相反，且转色期归类不同**，必须统一映射到业务类别：

| 来源 | 原类别 | 原 id | 映射到 |
|---|---|---|---|
| iTomato | green | 0 | **1 = tomato_G** |
| iTomato | ripe | 1 | **0 = tomato_R** |
| iTomato | ripening（转色期） | 2 | **1 = tomato_G** ⚠️ |
| Kaggle | unriped | 0 | **1 = tomato_G**（需 0↔1 互换） |
| Kaggle | riped | 1 | **0 = tomato_R**（需 0↔1 互换） |

映射脚本核心：

```python
# iTomato：ripe(1) → R(0)，其余 → G(1)
def remap_itomato(old_id):
    return 0 if old_id == 1 else 1

# Kaggle：类别顺序相反，做 0↔1 互换
def remap_kaggle(old_id):
    return 1 - old_id
```

### 4.3 data.yaml（可移植写法）

```yaml
path: ./datasets          # 相对路径，不写死盘符，跨平台通用
train: train/images
val:   val/images
test:  test/images

names:
  0: tomato_R    # 成熟（红/橙红），唯一采摘目标
  1: tomato_G    # 未成熟（绿/浅橙），干扰目标
```

> **坑**：`path` 不要写绝对路径，换机器会失效；用相对路径并从项目根目录运行。

## 5. 数据标注与标准统一

### 5.1 数据是题目，标注是答案

模型通过"做题对答案"来学习，**标注质量直接决定模型上限**。

### 5.2 标注工具：X-AnyLabeling

- 打开图片目录 → 多边形工具（快捷键 `P`）沿番茄边缘描点；
- 选择标签 tomato_R / tomato_G；
- 每张 `Ctrl+S` 保存，产出与图片同名的 json。

**导出 YOLO-seg 的勾选项：**

1. 格式选 **YOLO Segmentation**；
2. 勾选 **Save labels only**（不重复导出图片）；
3. 勾选 **Skip unlabeled images**（跳过空标注图）；
4. **不要**勾选 "Save image with results"。

### 5.3 标注标准统一（核心攻坚）

**问题**：两个数据集对"转色期/偏橙"的归类互相矛盾：

- iTomato 把转色期归为**未熟**；
- Kaggle 把"开始转橙"标为**成熟**。

直接融合会让模型把偏橙番茄高置信度判成成熟，违背项目核心。

**解决**：

1. 统一规则：**只有全红才是 tomato_R，偏橙/转色期一律 tomato_G**；介于浅橙和橙红之间的，由人工逐张分辨；
2. 开发可视化工具逐张核查所有含成熟标注的图片；
3. 共修正 **89 个误标实例**，删除 2 张无法判断的图。

> **经验**：多数据集融合前必须核对标注口径，否则模型会学到错误规律，这是视觉项目最常见的隐性坑。

> 完整标注操作、标签规范与问题处理见配套《番茄数据集标注方法手册》。

## 6. 仿真数据接入（Gazebo → 训练）

### 6.1 为什么补仿真数据

实拍数据缺三类难样本：

1. 被植株遮挡一部分的番茄 → 检出率低；
2. 画面里小尺寸番茄 → 置信度低；
3. 未成熟绿番茄与植株颜色相近 → 容易漏检。

Gazebo 能低成本、大批量生成这些难样本。

### 6.2 导出与解压（Windows 文件名坑）

- 截取 110 张 PNG（约 128MB，1435×963）；
- **坑**：Gazebo 文件名带冒号 `:`，Windows 资源管理器直接解压会失败；
- **解决**：用 Python `zipfile` 解压并把 `:` 替换为 `_`。

```python
import zipfile
with zipfile.ZipFile("pictures.zip") as z:
    for info in z.infolist:
        info.filename = info.filename.replace(":", "_")
        z.extract(info, "extracted_py/")
```

### 6.3 仿真图标注与合并

- 110 张手工标注，共 **937 个实例**：tomato_R 853 / tomato_G 84；
- 写脚本 `json_to_yolo.py`（json→txt）、`merge_sim.py`（按 85/15、seed=42 合并）。

合并后规模：

| 集合 | 原实拍 | + 仿真 | 合计 |
|---|---|---|---|
| train | 582 | 94 | **676** |
| val | 102 | 16 | **118** |

## 7. 模型训练

### 7.1 训练脚本（train_seg7.py）

```python
from ultralytics import YOLO

if __name__ == "__main__":          # Windows 多进程必须加，否则报错
    model = YOLO("yolov8n-seg.pt")  # 预训练起步（迁移学习）
    model.train(
        data="data/data.yaml",
        epochs=150,
        batch=8,
        imgsz=960,          # 高分辨率，专攻小目标/边缘
        device=0,
        amp=False,          # 关闭混合精度，规避本环境自检超时
        copy_paste=0.1,     # 复制粘贴增强，模拟遮挡
        patience=50,        # 早停
        seed=0,
        workers=2,
    )
```

### 7.2 关键超参

| 参数 | 作用 |
|---|---|
| epochs / patience | 训练轮数 / 早停，防过拟合和无谓等待 |
| batch | 每批图数，受显存限制（8GB 用 8） |
| imgsz | 输入分辨率，**推理时要与训练对齐** |
| amp | 混合精度；本环境自检超时，故关闭 |
| copy_paste | 把目标复制粘贴，模拟遮挡 |
| hsv_h/s/v | 色调/饱和度/亮度抖动，模拟光照 |
| mosaic / close_mosaic | 四宫格增强，最后 10 轮关闭收尾 |
| seed | 固定随机种子，保证可复现 |

### 7.3 迭代历程

| 轮次 | 数据 | imgsz | epochs | 说明 |
|---|---|---|---|---|
| smoke | 小样本 | 640 | 3 | 冒烟测试，先验证链路 |
| seg-3 | 550 iTomato | 640 | 150 | 首轮完整训练 |
| seg-4 | 672（+Kaggle） | 640 | 150 | 扩数据 |
| seg-5 | 670（修正标注） | 640 | 150 | 统一标准 |
| seg-6 | 684（人工复核） | 640 | 109 早停 | 旧交付 |
| **seg-7** | 794（+110 仿真） | **960** | 150 | **最终模型** |

> **冒烟测试**：先 3 个 epoch 快速验证环境、数据、代码，避免跑几小时才发现数据错误。

## 8. 模型评估

### 8.1 最终指标（best.pt，epoch 81）

| 指标 | 数值 |
|---|---|
| **Box mAP50** | **0.836** |
| **Mask mAP50** | **0.834** |
| Mask mAP50-95 | 0.638 |
| Mask Precision / Recall | 0.869 / 0.732 |

- 训练总时长约 **4973 秒（83 分钟）**；
- best 出现在第 81 轮，之后略有波动，部署用 `best.pt`。

### 8.2 多轮对比

| 轮次 | Mask mAP50 | 备注 |
|---|---|---|
| seg-3 | 0.833 | |
| seg-5 | 0.838 | 数值最高 |
| seg-6 | 0.821 | val 集换过 |
| **seg-7** | **0.834** | 高分辨率 + 仿真数据，泛化更好 |

> 各轮验证集不完全相同，数值不能直接横比；实测主观判定 seg-6/seg-7 泛化更好。

### 8.3 多维评估方式

1. 混淆矩阵：看类别互相混淆；
2. PR 曲线：看精度-召回权衡；
3. 验证集预测图：肉眼检查分割效果；
4. **没训练过的真实/仿真图测试，最重要**。

### 8.4 评估发现的真实问题

- 阴影/暗处的红番茄被误判为未熟；
- 被遮挡番茄检出率低；
- 小尺寸番茄置信度低；
- 绿番茄与植株相近容易漏检。

**结论**：数值高不代表真实场景好用，需持续补难样本。当前约 800 张，若需更好效果预估需要补充更多gazebo仿真数据。

## 9. 问题与解决方案汇总

| # | 问题 | 解决方案 |
|---|---|---|
| 1 | 原 yolov8 环境是空壳 | 重建标准环境 |
| 2 | torch 装成 CPU 版 | 指定 cu121 源 |
| 3 | Kaggle CLI 国内超时 | 浏览器直接下载 zip |
| 4 | 260 字符路径 / 文件名带冒号 | zipfile 解压替换非法字符 |
| 5 | 转色期归类冲突 | 人工统一"全红=成熟" |
| 6 | 两数据集 id 顺序相反 | 0↔1 互换 |
| 7 | Windows 多进程报错 | 加 `if __name__ == "__main__":` |
| 8 | AMP 自检超时 | amp=False |
| 9 | data.yaml 绝对路径失效 | 改相对路径 |
| 10 | onnx 预标"输出不兼容" | 放弃 AI 预标，改手工 |
| 11 | json 打开报错 | 含 `imageData: null` |
| 12 | 推理 imgsz 不一致 | 与训练对齐（seg-7 用 960） |
| 13 | 遮挡/小目标/绿番茄难识别 | 仿真数据 + 高分辨率 + copy_paste |
