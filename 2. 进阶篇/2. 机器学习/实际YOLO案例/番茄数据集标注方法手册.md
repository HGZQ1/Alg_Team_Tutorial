# 番茄数据集标注方法手册

统览
> 本手册针对**番茄果实实例分割标注**，讲解 X-AnyLabeling 的操作、标签规范、类别映射、成熟度判定，以及真实项目中遇到的问题与处理方法。
> 任何具体项目需求不同数据集处理方法都不一样，数据集处理标准需明确，本项目核心为采摘机器人识别成熟番茄进行机械臂及底盘规划采摘，实际使用并不需要对深度相机获得的画面识别画面中所有番茄，因此在最初已经确立标注原则。

## 1. 标注任务与标签规范

### 1.1 标注对象

- 标注对象是**一个个番茄果实**（不是整株植物，也不是叶子）；
- 每个果实一个独立 polygon，贴合果实外轮廓；
- 相邻果实、遮挡果实要分别标注，不能连成一个。

### 1.2 类别定义

| 类别 ID | 标签 | 含义 | 外观 |
|---|---|---|---|
| 0 | `tomato_R` | 成熟（可采摘） | 全红 / 橙红 |
| 1 | `tomato_G` | 未成熟（不摘） | 绿色 / 浅橙 / 转色期 |

### 1.3 标注粒度

- 一个果实一个 mask；
- 被叶片遮挡的果实，能看到的部分沿可见边缘描，被遮挡处按果实圆弧补全；
- 被画面边缘截断的，沿画面边界闭合。

## 2. 标注工具 X-AnyLabeling

### 2.1 为什么用它

- 单 exe 免安装，环境依赖少；
- 支持 polygon 手工标注、AI 辅助、导入已有标签；
- 直接读写 labelme 风格 json，可导出 YOLO 格式；
- 数据全部在本机，不在云端，适合中小型模型。

### 2.2 界面认识

- 左侧：文件列表 / 标签列表；
- 中间：画布；
- 工具栏：打开目录、保存、多边形工具（快捷键 `P`）、AI 功能等；
- 不同版本菜单位置可能不同，按功能名找即可。

---

## 3. 导入图片与设置标签

### 3.1 打开图片目录

- 用"打开目录 / Open Dir"选择存放番茄图片的文件夹；
- 标注结果默认保存为**同名、同目录的 json**。

### 3.2 建立标签

- 在标签列表里预先建好 `tomato_R`、`tomato_G`，标注时直接选择；
- 标签的"输入链接 / input link"是给 AI 模型预标用的，**纯手工标注不需要设置**。

### 3.3 文件名注意

- 图片和 json 必须同名、同目录；
- Gazebo 导出的图片文件名可能带冒号 `:`，Windows 不支持，需在解压时用脚本替换为 `_`（见第 8 章）。

---

## 4. 绘制 polygon（番茄果实）

### 4.1 操作步骤

1. 选择多边形工具（`P`）；
2. 沿番茄果实边缘逐点单击；
3. 绕完一圈闭合；
4. 选择标签 tomato_R 或 tomato_G；
5. `Ctrl+S` 保存。

### 4.2 点位技巧（番茄近圆形）

- 番茄近似圆形/椭圆，沿圆弧均匀布点，一般 **8~12 个点**即可贴合；
- 有明显凹凸、被遮挡转折处加点；
- 点位太少会变成多边形棱角，mask 不圆润；
- 遮挡果实：可见边缘贴合，遮挡段按圆弧平滑补全。

### 4.3 修改

- 拖动顶点、加/删顶点调整轮廓；
- 错误 polygon 直接删除重画；
- 改完立即保存。

## 5. 保存与导出 YOLO 格式

### 5.1 保存的 json 结构

X-AnyLabeling 保存 labelme 风格 json，核心字段：

```json
{
  "shapes": [
    {"label": "tomato_R", "points": [[x,y], ...], "shape_type": "polygon"}
  ],
  "imagePath": "xxx.jpg",
  "imageData": null,
  "imageWidth": 0,
  "imageHeight": 0
}
```

### 5.2 导出 YOLO-seg 的勾选项

1. 格式选 **YOLO Segmentation**；
2. 勾选 **Save labels only**（不重复导出图片）；
3. 勾选 **Skip unlabeled images**（跳过空标注图）；
4. **不要**勾选 "Save image with results"。

### 5.3 输出格式

YOLO txt 每行一个果实，坐标归一化到 0~1：

```
类别id x1 y1 x2 y2 ...
```

转换公式：`归一化x = 像素x / 图片宽`，`归一化y = 像素y / 图片高`。

## 6. 多数据集的类别映射

### 6.1 为什么要映射

不同数据集的类别 id 顺序、类别数量都不同，直接合并会把类别标乱。

### 6.2 本项目映射表

| 来源 | 原类别（原 id） | 映射到 |
|---|---|---|
| iTomato | green (0) | tomato_G (1) |
| iTomato | ripe (1) | tomato_R (0) |
| iTomato | ripening (2) | tomato_G (1) |
| Kaggle | unriped (0) | tomato_G (1)，0↔1 互换 |
| Kaggle | riped (1) | tomato_R (0)，0↔1 互换 |

### 6.3 映射脚本核心

```python
def remap_itomato(old_id):
    return 0 if old_id == 1 else 1

def remap_kaggle(old_id):
    return 1 - old_id      # 0↔1 互换
```

> 合并后务必抽样核对：标签名、类别 id、坐标范围是否正确，避免"红番茄被标成 G"这类低级错误。

## 7. 成熟度判定标准（核心）

### 7.1 统一规则：全红才是成熟

- **tomato_R**：果实整体全红/橙红，没有明显绿色区域；
- **tomato_G**：全绿、浅橙、转色期（红绿相间），一律算未成熟。

### 7.2 偏橙果实的判定（最容易出错）

- 两个原始数据集对"转色期"的归类互相矛盾，是本项目最大的隐性坑；
- 统一后，**介于浅橙和橙红之间的果实由人工逐张判断**，拿不准时从严——归 tomato_G（不摘比错摘安全）；
- 项目中通过可视化工具逐张核查，修正了 89 个误标实例，删除 2 张无法判断的图。

### 7.3 判定口径先对齐

开标前先用几张典型样例（全红、转色、全绿、遮挡）统一全队标准，再进行标注。

## 8. 常见问题与处理

| 问题 | 原因 | 处理 |
|---|---|---|
| json 打开报错 | 缺少 `imageData` 字段 | 保证 json 含 `imageData: null` |
| 标注不显示 | 图片/json 不同名或不同目录；格式不匹配 | 检查同名同目录；导入选项选 labelme/polygon 格式 |
| onnx 自动预标报"输出不兼容" | 模型输出与软件不匹配 | 放弃 AI 预标，改纯手工 |
| 解压失败/文件名非法 | Gazebo 文件名带冒号 | 用 zipfile 解压并替换 `:` 为 `_` |
| 路径过长 | Windows 260 字符限制 | 缩短目录、用脚本处理 |
| 类别标反 | 数据集 id 顺序相反 | 合并时 0↔1 互换并抽样核对 |
| 标签名对不上 | 手工拼写/大小写错误 | 用标签列表选择，不手敲 |
| polygon 被忽略 | 点数少于 3 | 保证至少 3 点 |
| 坐标越界 | 点超出图片范围 | 转换时裁剪到 [0,1] |

### 8.1 文件名带冒号的解压脚本

```python
import zipfile
with zipfile.ZipFile("pictures.zip") as z:
    for info in z.infolist():
        info.filename = info.filename.replace(":", "_")
        z.extract(info, "extracted_py/")
```

## 9. 未预料问题的处理思路

1. **先备份再批量修改**：原始数据完整备份后再动手；
2. **批量操作先小样本验证**：映射、转换规则先在 5~10 张上验证；
3. **隔离而非删除**：无法判断的图片移到单独目录保留，可回溯；
4. **拿不准从严**：成熟度存疑时归 tomato_G，避免错误采摘；
5. **自动路径走不通就换手工**：AI 预标两次失败就果断回退，不反复硬试；
6. **沉淀经验**：把坑和解决办法记录下来，形成团队知识库。

## 10. 标注质量检查清单

- [ ] 每个果实都有独立 polygon，无连株、无遗漏；
- [ ] 标签名只有 tomato_R / tomato_G，无错别字；
- [ ] 全红才是 R，偏橙/转色期归 G，判定一致；
- [ ] 遮挡果实轮廓补全合理，点位贴合；
- [ ] 每个 polygon 至少 3 点，坐标在 0~1；
- [ ] 图片与标签一一对应，无空标注、无多余文件；
- [ ] 多数据集类别映射正确，抽样核对无标反；
- [ ] 原始数据已备份，问题样本已隔离；
- [ ] data.yaml 类别顺序与 txt 中 id 一致。

## 11. 团队协作规范

1. 开标前统一标签名、判定标准、工具版本；
2. 按文件随机分工，避免重复；
3. 发给队友的待标数据单独打包并附说明；
4. 回收后统计图片数、各类实例数，核对格式与口径；
5. 划分训练/验证集时固定随机种子（seed=42），保证可复现；
6. 数据与脚本用 Git 管理，修改可追溯；
7. 持续维护本手册，供后续成员复用。
