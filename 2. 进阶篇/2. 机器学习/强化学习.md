# 强化学习与四足机器人（狗子）

这一章讲的是近几年腿足机器人领域最火的一条技术路线：**用强化学习（Reinforcement Learning，RL）让四足机器人自己学会走路、跑步、甚至跑酷**——也就是你们在各种视频里看到的宇树 Go2 / B2 那些"狗子"的核心科技之一。

传统机器人控制是"人写规则、机器执行"，而 RL 的思路完全相反：**你只告诉它什么叫'走得好'，它自己在仿真里摔几百万次，把走路学会。**

这一章只做基础介绍，目标是你看完能读懂那些开源项目和论文在干什么，而不是手推公式。数学细节和调参玄学，留到你真正上手训练时再补。

## 本章学习目标

完成本章后，你应当能够：

- 说清楚强化学习和监督学习的区别，以及**智能体、环境、状态、动作、奖励、策略**这几个词各自是什么；
- 理解 PPO 为什么是四足运动控制的主流算法；
- 说清楚用 RL 训狗的完整流程：**仿真环境 → 设计观测/动作/奖励 → 域随机化 → 训练 → 部署到真机**；
- 知道该装什么、跑什么、读什么，迈出上手第一步。

## 1. 强化学习是什么

### 1.1 从训（真）狗说起

你训过狗吗？训狗的方式是这样的：狗做了一个动作，做对了就给零食，做错了就没有。久而久之，狗学会了一套"在什么情况下做什么动作能拿到最多零食"的策略。

强化学习和这个过程一模一样，只是：

- 把狗换成了**模型**（通常是一个神经网络）；
- 把零食换成了**奖励（reward）**——一个由你定义的数字；
- 把"什么情况下"换成了**状态（state）**——机器人当前的感知输入；
- 把"做什么动作"换成了**动作（action）**——模型输出的控制量。

所以 RL 的本质一句话：**让一个智能体在不断试错中，学会让长期累积奖励最大的行为策略。** 我们要做的"训练狗子"，字面意义上就是在训狗。

### 1.2 和监督学习的区别

| | 监督学习 | 强化学习 |
|---|---|---|
| 数据 | 人工标注好（图片→标签） | 与环境交互自己产生 |
| 反馈 | 每个输入都有标准答案 | 只有一个（延迟的）奖励信号 |
| 目标 | 拟合标签 | 最大化长期累积奖励 |
| 典型任务 | 分类、检测、分割 | 游戏、运动控制、决策 |

关键区别有两个：

**第一，没有标准答案。** 没有人告诉狗"此刻应该迈左脚"——那正是我们要学的东西。我们只能评价"这么走整体上好不好"，而不能演示"每一步该怎么做"。

**第二，反馈是延迟的。** 狗摔倒发生在错误决策的几秒之后。如何把"最终摔倒了"这个信号归因到"当初哪一步迈错了"，本身就是 RL 算法要解决的核心问题（叫**信用分配问题**）。

### 1.3 六个核心术语

RL 的文献翻起来吓人，但核心角色就六个：

- **智能体（Agent）**：做决策的主体，就是那个神经网络；
- **环境（Environment）**：智能体交互的对象，训练时是物理仿真器，部署后是真机；
- **状态（State）/ 观测（Observation）**：智能体看到的输入。严格说"状态"是环境的完整描述，"观测"是智能体实际能拿到的部分（比如狗子感知不到自己的真实速度，只能看到 IMU 和编码器读数）；
- **动作（Action）**：智能体的输出，对狗子来说是 12 个关节的目标角度；
- **奖励（Reward）**：环境每一步返回的一个数字，"这步干得好不好"；
- **策略（Policy，记作 $\pi$）**：从观测到动作的映射，$\pi(a|s)$ 表示在状态 $s$ 下选动作 $a$ 的概率。**策略就是我们最终要的东西。**

它们的关系一图流：

```text
            ┌─────── action a_t ───────┐
            │                          ▼
      ┌───────────┐              ┌───────────┐
      │  Agent    │              │Environment│
      │ (策略网络π)│              │ (仿真器)   │
      └───────────┘              └───────────┘
            ▲                          │
            └── obs s_t+1, reward r_t ──┘
```

### 1.4 数学化：MDP

RL 问题通常被建模为**马尔可夫决策过程（Markov Decision Process，MDP）**，由五元组描述：

$$ \mathcal{M} = (\mathcal{S}, \mathcal{A}, P, r, \gamma) $$

- $\mathcal{S}$：状态空间；$\mathcal{A}$：动作空间；
- $P(s'|s,a)$：状态转移概率——执行动作 $a$ 后环境变成什么样；
- $r(s,a)$：奖励函数；
- $\gamma \in (0,1)$：折扣因子，通常取 0.99。

训练的目标是最大化**期望累积回报**：

$$ J(\pi) = \mathbb{E}_{\pi} \left[ \sum_{t=0}^{T} \gamma^t r_t \right] $$

$\gamma$ 的直观含义是"未来的奖励打几折"：$\gamma=0.99$ 意味着 100 步之后的奖励约等于现在的 37%。太小，狗子会变得短视（只顾眼前不摔）；太大，训练会不稳定。

还有一个重要概念是**价值函数**，评估"从这个状态出发、按策略 $\pi$ 走下去，总共能拿多少奖励"：

$$ V^\pi(s) = \mathbb{E}_\pi \left[ \sum_t \gamma^t r_t \mid s_0 = s \right] $$

它派生出的**优势函数（Advantage）**$A(s,a)$ 表示"动作 $a$ 比平均水平好多少"，PPO 这类算法就是靠它来决定"把哪个动作的概率往上加"。

到这个深度就够了。再往下的贝尔曼方程、Q 函数、各种收敛性证明，属于进阶内容，入门阶段可以先背结论。

## 2. 算法速览：为什么是 PPO

RL 算法有一大家子，按思路分三大类：

| 类别 | 代表 | 一句话 |
|---|---|---|
| 基于价值（Value-based） | DQN | 学"每个动作多好"，间接导出策略，只适合离散动作 |
| 基于策略（Policy-based） | REINFORCE | 直接对策略求梯度，简单但方差大 |
| 演员-评论家（Actor-Critic） | **PPO**、SAC、TD3 | 前两者结合：一个网络输出动作（Actor），一个评估好坏（Critic） |

**四足运动控制的事实标准是 PPO（Proximal Policy Optimization，近端策略优化）**，原因很实际：

1. **稳。** PPO 的核心思想是"每次更新只走一小步"（对策略更新幅度做裁剪），不像某些算法动不动训练崩掉归零。调参容错率高，适合新手；
2. **够快。** PPO 是 on-policy 算法，样本利用效率低——这个缺点在别处是致命的，但在 GPU 并行仿真面前不是事：一卡 4090 同时跑 4096 只狗，几十亿步样本说来就来，"暴力"就能补上样本效率；
3. **生态成熟。** ETH Zürich 的 legged_gym、宇树的官方示例、绝大数论文复现，全是 PPO。

顺便记两个词：**on-policy**（只能用当前策略产生的数据训练，PPO）和 **off-policy**（能反复利用旧数据，SAC/TD3）。机械臂抓取这类没有大规模并行仿真的任务，更常用样本效率高的 SAC。

## 3. 为什么狗子用 RL，而不是传统控制

在 RL 走红之前，四足机器人靠 **MPC（模型预测控制）** 走路（MIT Cheetah 的经典方案），现在很多产品依然在用。两条路线的对比如下：

| | MPC（传统） | RL（学习） |
|---|---|---|
| 依赖 | 精确的动力学模型 | 仿真环境 + 奖励设计 |
| 求解 | 每步在线优化（解 QP），吃算力 | 一次神经网络前向传播，微秒级 |
| 步态 | 人工设计/预设周期步态 | 自己学出来，自然涌现 |
| 鲁棒性 | 受模型误差限制 | 见过大量随机扰动，被踹一脚能稳住 |
| 可解释性 | 有理论保证 | 黑盒，不保证最优和安全 |
| 开发方式 | 建模 + 调控制器 | 调奖励 + 调随机化（也是玄学） |

RL 真正的杀手锏是：**仿真里摔一百万次不要钱。** 传统方法最头疼的地面接触（脚和地面何时接触、接触力多大）本质上是高度非线性的混合动力学，很难精确建模；而 RL 根本不需要精确模型——仿真只要"足够像"，再把"不像的部分"用随机化盖住（见 4.5 节），策略就能迁移到真机上。

当然也要诚实地说 RL 的坑：奖励设计是玄学重灾区（狗子会钻空子骗奖励，见 4.4 节），sim-to-real 有 gap，且没有任何理论保证它学出来的策略绝对安全。目前工业界的做法往往是两条路线混用。

## 4. 完整技术路线：从零到一只会走路的狗

这是本章的核心。以宇树 Go2（12 自由度：4 条腿 × 髋/大腿/小腿各 1 个关节）+ ETH legged_gym 风格的方案为例，走一遍全流程。

### 4.1 仿真环境

RL 训练的第一件事：选一个物理仿真器当"环境"。

| 仿真器 | 特点 | 用途 |
|---|---|---|
| **Isaac Gym / Isaac Lab** | NVIDIA 出品，GPU 并行物理仿真，4096 只狗同时跑 | 运动控制训练的主流 |
| MuJoCo | DeepMind 出品，接触动力学精度高，单场景速度慢 | 学术研究、机械臂 |
| PyBullet | 轻量、纯 Python、好装 | 入门玩具级任务 |
| Gazebo | ROS 系标配仿真器 | 做 SLAM/导航验证，没人拿它训 RL（太慢） |

关键指标是**并行环境数**：PPO 是数据怪兽，Isaac Gym 把物理仿真整个搬进 GPU，才能做到单卡几千只狗并行、一小时出头收敛一个策略。这也是 Rudin 等人 2021 年那篇《Learning to Walk in Minutes Using Massively Parallel Deep RL》的核心贡献。

### 4.2 定义观测（Observation）

观测就是"策略网络每一步看什么"。以 Go2 为例，典型的本体感知（proprioception）观测是一个约 45 维的向量：

```text
[ 基座角速度 (3)        ← IMU 陀螺仪
  重力方向投影 (3)       ← IMU 姿态解算（指示身体有多歪）
  速度指令 (3)          ← 操作手给的 x / y / yaw 期望速度
  关节角度 (12)         ← 编码器
  关节速度 (12)         ← 编码器差分
  上一步动作 (12)       ← 自己上一步的输出 ]
```

设计观测有一条铁律：**真机上拿不到的东西，观测里就别有。** 训练时作弊给它真实速度、给它上帝视角的地形高度图，它学得又快又好——一上真机立刻趴窝。真机狗子没有精准的全局速度传感器，也看不见脚下的台阶，那训练时就只用 IMU 和编码器这些真机有的东西。（特权信息确实有用，处理方式见 4.7 节 teacher-student。）

### 4.3 定义动作（Action）

动作是 12 维：每个关节一个目标角度（通常表示为相对默认站姿的偏移量）：

$$ \mathbf{q}_{target} = \mathbf{q}_{default} + \mathbf{a} $$

注意策略并不直接输出力矩。整个控制系统是分层的：

```text
┌────────────────────────────────────────────────┐
│  策略网络 (板载计算机, ~50 Hz)                    │
│  观测 45 维 → MLP → 12 个目标关节角               │
└──────────────────┬─────────────────────────────┘
                   ▼
┌────────────────────────────────────────────────┐
│  PD 控制器 (电机控制板, 500 Hz ~ 1 kHz)          │
│  τ = kp·(q_target − q) − kd·q̇                   │
└──────────────────┬─────────────────────────────┘
                   ▼
              12 个电机力矩
```

也就是说，**RL 学的是"落脚姿态"这个层面的事，力矩层面的快、硬、准还是交给经典 PD**。这种分层让策略的网络可以很小、推理可以很快，也降低了学出毁灭性力矩的概率。

### 4.4 设计奖励（Reward）——最核心也最玄学的一环

总奖励是一堆项的加权和：

$$ r_t = \sum_i w_i \cdot r_i(s_t, a_t) $$

以 legged_gym 的典型配置为例，感受一下"告诉狗子什么叫走得好"是怎么拆解成数学式的：

| 奖励项 | 含义 | 典型形式 |
|---|---|---|
| tracking_lin_vel | 跟踪 x/y 方向速度指令 | $e^{-\|\mathbf{v}_{cmd}-\mathbf{v}\|^2}$，权重 +1.0 |
| tracking_ang_vel | 跟踪 yaw 角速度指令 | 同上，权重 +0.5 |
| feet_air_time | 鼓励迈步（脚在空中时间） | 正奖励 |
| orientation | 身体别歪（重力投影的 xy 分量小） | 惩罚 |
| lin_vel_z | 上下蹦跶惩罚 | 惩罚 |
| ang_vel_xy | 侧翻/俯仰角速度惩罚 | 惩罚 |
| torques / dof_acc | 省力、别暴力 | 惩罚 |
| action_rate | 动作别抖 | 惩罚 |
| collision | 膝盖/大腿别蹭地 | 惩罚 |
| stand_still | 指令为零时老老实实站着 | 惩罚 |

**每写一个奖励项，狗子都会认真钻研怎么用最不要脸的方式拿到它。** 这叫 reward hacking，是 RL 训练的日常：

- 惩罚"耗能"，狗子学会四条腿蜷成一团贴地"漂移"，因为摩擦比走路省电；
- 奖励"抬脚时间"，狗子学会单脚金鸡独立摆pose；
- 速度奖励权重太高，狗子学会往前扑摔一跤——摔了 episode 重置，但那一下速度奖励已经到账了。

调奖励基本是"改一项、训一次、看tensorboard、骂一句"的循环，直到狗子走出你想要的样子。没有一步到位的方法论，只有多摔多改积累的直觉。

### 4.5 域随机化（Domain Randomization）：Sim-to-Real 的关键

**Sim-to-real gap**：仿真里的狗和真狗永远有差异——仿真摩擦系数是干净的一个数，真橡胶脚垫踩水泥地、草地、塑料板各不相同；仿真指令瞬时到达，真机有 10~30 ms 通信延迟。

如果策略只见过一种"完美仿真"，上真机必死。解决办法简单粗暴：**每个回合把仿真的物理参数随机一遍**，逼策略学出一套对参数不敏感的走法：

- 摩擦系数 ~ U(0.5, 1.25)；
- 整机质量随机 ±10%（模拟驮负载）；
- 质心位置随机偏移；
- 电机强度（力矩缩放）±20%；
- PD 增益扰动；
- 观测加噪声；
- **随机外力**：训练中随机时刻给狗一记横踹（push robot），这就是为什么 RL 狗被踹一脚晃一下能稳住——训练时被踹过几千次；
- 动作延迟随机 0~15 ms（把真机通信延迟纳入训练）。

再加一个**地形课程（terrain curriculum）**：从平地开始，走稳了逐步换粗糙地形、台阶、斜坡。思路简单，但对最终性能影响巨大。

### 4.6 训练过程

PPO 的训练循环，伪代码就这么多：

```text
初始化策略网络 π (Actor) 和价值网络 V (Critic)
repeat:
    4096 只狗并行跑 24 步，收集 (s, a, r) 样本
    用 V 计算 GAE 优势估计 A(s, a)
    小步幅裁剪更新 π（几个 epoch，防止单步走太远）
    回归目标更新 V
until 奖励曲线收敛
```

网络结构小得离谱：一个 3 层 MLP（隐层 [512, 256, 512]，ELU 激活），总共约几十万参数——和视觉组天天碰的 YOLO 比是毛毛虫。整个训练单张 4090 跑 1~2 小时。

**在仿真器 GUI 里看几千只小狗从抽搐、爬行、踉跄到齐刷刷迈步的过程，是 RL 最治愈的画面，建议每个人都亲眼看看。**

### 4.7 部署到真机

训练收敛后，把策略导出、塞到狗身上：

```text
PyTorch 模型 (.pt)
   → 导出 ONNX
   → 部署到板载计算机 (Jetson Orin / NX 等)
   → onnxruntime / TensorRT，50 Hz 推理
   → 输出 12 个目标关节角
   → 官方低层接口 (unitree_sdk2) 下发
   → 电机控制板 PD 环 (500 Hz+) 执行
```

真机调试时的头号大坑就是**延迟**：策略输出 → 通信 → 电机响应这条链路如果比仿真里慢 20 ms，狗子可能直接走不稳。这就是 4.5 节坚持要加延迟随机化的原因。此外 IMU 坐标系方向、关节顺序、默认站姿角度这些"显然应该对齐"的细节，每一个都能让你查一晚上。

### 4.8 进阶：Teacher-Student（特权学习）

4.2 节说过"真机拿不到的信息不能进观测"，但"仿真里才知道的真值"（真实线速度、精确地形高度图）对学习确实帮助很大。怎么办？分两步：

1. **Teacher**：训练时喂特权信息，学出一个强壮的"上帝视角"教师策略；
2. **Student**：只看本体感知观测（和真机一致），模仿 Teacher 的输出（知识蒸馏）。由于 Student 的输入里没有特权信息，它得从关节历史里"脑补"出速度和地形。

walk-these-ways、极限跑酷（extreme parkour）等知名工作都是这条路线。到这一步，恭喜你，已经摸到当前四足运动控制的研究前沿了。

## 5. 上手路线建议

**Step 0：前置。** Python 熟练、PyTorch 会搭网络、线性代数和概率论基本概念还在。没有的话先回炉，直接上 RL 会连报错都看不懂。

**Step 1：经典入门任务。** `pip install gymnasium`，把 CartPole（倒立摆）用现成 PPO 代码跑通，盯着 reward 曲线从 20 涨到 500，建立"训练"的体感。

**Step 2：读两篇东西。**

- Schulman et al., *Proximal Policy Optimization Algorithms*, 2017 —— PPO 原文，短，值得精读；
- Rudin et al., *Learning to Walk in Minutes Using Massively Parallel Deep RL*, 2021 —— legged_gym 的出处，大规模并行训练的奠基作。

**Step 3：跑通 legged_gym。** GitHub 搜 `leggedrobotics/legged_gym`（配 `rsl_rl`），需要 Linux + N 卡。先在平地复现官方 Go2/ANYmal 配置，然后做三件事练手：改速度指令范围、加一种新地形、改一个奖励项权重，观察狗子步态怎么变。

**Step 4：（有条件的话）上真机。** 宇树 Go2 教育版开放低层接口，社区有 walk-these-ways-go2 等开源部署项目可以直接对照学习。**第一次让真狗跑自己训的策略之前：把狗吊起来、人站远点、随时按急停。**

课程推荐：Berkeley CS285（Deep RL，网课免费）、OpenAI Spinning Up（理论 + 代码实现，入门最友好的文字教材）。

## 6. 术语速查表

| 术语 | 一句话解释 |
|---|---|
| MDP | 马尔可夫决策过程，RL 问题的数学骨架 (S, A, P, r, γ) |
| Policy π | 策略，观测到动作的映射，训练的最终产物 |
| Reward | 每步的即时评分，训练的唯一定向信号 |
| Return | 累积（折扣）奖励之和，优化的目标 |
| Value function V | 从某状态出发未来能拿多少总奖励的期望 |
| Advantage A | 某动作比该状态的平均水平好多少，PPO 更新的依据 |
| on-policy / off-policy | 只用当前策略的数据 / 能复用旧数据 |
| Actor / Critic | 出动作的网络 / 打分评估的网络 |
| Episode | 从开局到结束（比如狗摔倒）的一整轮交互 |
| Sim-to-real | 从仿真策略迁移到真机的技术总称 |
| Domain randomization | 训练时随机化物理参数，逼策略鲁棒 |
| Privileged learning | Teacher 用仿真特权信息训练，Student 蒸馏到纯本体感知 |
| Proprioception | 本体感知：只有 IMU + 编码器，不靠外部传感器 |

## 7. 写在最后

强化学习和视觉是当下"具身智能"的两条腿：视觉负责"看见世界"，RL 负责"动起来"。四足运动控制是 RL 目前落地最扎实的场景之一——任务定义清晰（跟踪速度指令）、仿真便宜（GPU 并行）、验证直观（狗子稳不稳一眼可见），非常适合作为你接触 RL 的第一站。

这篇介绍覆盖到"能看懂别人在干什么"的深度。从"看懂"到"训出自己的一条狗"，中间隔着：奖励调参的手感、随机化范围的选择、和真机上无数个对不上的坐标系。这些东西没有教程，只有亲手摔出来的经验。**去吧，先在仿真里摔够一百万次。**
